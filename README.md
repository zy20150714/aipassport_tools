# 超级工具箱 · 云端服务

给 FoloToy AI Passport(ESP32-C3)超级工具箱固件用的云端同步服务。

一个 Cloudflare Worker,**同时提供两样东西**:

- **一个手机能用的管理网页** —— 打开网址就能改数据,不用碰代码
- **设备要的数据接口** —— 设备连上网自动来拉

---

## 为什么是单文件

管理网页是**内嵌在 `worker.js` 里**的字符串,不是独立的 html 文件。

这样做的原因很实际:Cloudflare 的网页上传入口对多文件支持不稳定,
而且碰到 `wrangler.toml` 会直接拒绝。内嵌成一个文件之后,
无论走哪条路部署(网页编辑器粘贴、GitHub 连接、命令行)都不会出问题。

代价是 `worker.js` 有 21 KB,读起来会长一些 —— 但部署的可靠性更重要。

## 这个仓库怎么部署

### 走 GitHub 连接(推荐)

1. Cloudflare 后台 → **Workers & Pages** → **Create application**
2. 选 **Import a repository**
3. 授权并选中本仓库
4. 构建配置:

   | 配置项 | 填什么 |
   |---|---|
   | 构建命令 | **留空** |
   | 部署命令 | `npx wrangler deploy` |
   | 根目录 | `/`(默认) |

5. 点 **Deploy**

> **构建命令必须留空。** 这个 Worker 是单文件、零依赖,没有构建过程。
> 填了 `npm install` 只会白跑一轮,还可能因为找不到依赖而失败。
>
> `wrangler.toml` 会被 Cloudflare 自动读取,里面的 **KV 绑定会自动生效** ——
> 这是走 GitHub 连接最大的好处,不用再去后台手动加绑定。

### 走命令行

```bash
npm install
npx wrangler login
npx wrangler deploy
```

### 走网页编辑器(不推荐)

把 `worker.js` 的内容全选复制,粘到 Cloudflare 的 Edit Code 编辑器里部署。

⚠️ 这种方式**不会**读取 `wrangler.toml`,所以 KV 绑定配不上,
Worker 会跑在「只读模式」—— 能看能改,但存不下来。

## KV 绑定

`wrangler.toml` 里已经配好了:

```toml
[[kv_namespaces]]
binding = "TOOLBOX_KV"
id = "52ae37eb729f44ee9f3fd1db43481f3b"
```

**绑定名 `TOOLBOX_KV` 不能改** —— `worker.js` 里写死了读 `env.TOOLBOX_KV`。
改了这里不改那里,Worker 会一直停在只读模式。

### 有没有 KV 都能跑

| | 没有 KV 绑定 | 有 KV 绑定 |
|---|---|---|
| 打开管理网页 | ✅ | ✅ |
| 编辑数据 | ✅ | ✅ |
| **保存** | ❌ 顶部橙条提示 | ✅ |
| 设备拉数据 | ✅ | ✅ |

所以可以先不配 KV 直接部署看看效果,想让它真能存再补绑定。

## 接口一览

设备端固件只用前两个。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/pull/<名字>` | 设备拉某一类数据 |
| GET | `/api/manifest` | 数据概览(调试用) |
| GET | `/api/admin/load` | 管理网页读全部数据 |
| POST | `/api/admin/save` | 管理网页存某一类数据 |
| GET | `/` 或 `/admin` | 管理网页 |

`<名字>` 只能是这五个之一:

`todo`(作业清单)、`travel`(出行规划)、`anniv`(纪念日)、
`settings`(设备设置)、`vault`(Wi-Fi 密码库)

### 关于 404

**空的项返回 404,不是空数组。** 这是有意的:

设备把 404 理解成「云端没有这项」→ **跳过,保留自己那份数据**。
如果这里返回一个空数组,设备会理解成「云端说这项是空的」→ **清光本地** ——
那是会丢东西的。所以空数组和空对象一律按 404 处理。

## 数据流向

```
   你在管理网页改
          │
          │ 点「保存作业清单」
          ▼
   ┌─────────────┐
   │   KV 存储    │
   └──────┬──────┘
          │
          │ 设备联网时来拉 /api/pull/xxx
          ▼
   ┌─────────────┐
   │    设备      │
   └─────────────┘
```

**设备不会自动知道云端改了。** 两种方式让它更新:

1. 在设备的「**云同步**」页面按一下**确定键**(手动刷新)
2. 或者重启设备(开机联网后自动拉一次)

## 安全提示

**整站没有任何鉴权。** 拿到网址的人就能读写全部数据。

其中「Wi-Fi 密码库」是**明文存储**的 —— 所以:

> ⚠️ **建议让密码库保持空白。** 真要放也请别放主路由的密码。

设备会保留它自己存在本地的那份密码,云端留空不影响设备使用。
